# Svitlo · Світло на Тернопільщині

Неофіційний додаток для перегляду графіків погодинних відключень АТ «Тернопільобленерго» за адресою.
Джерело: [poweron.toe.com.ua](https://poweron.toe.com.ua/).

## Віджети Android 0.5.0

Затисніть порожнє місце на головному екрані Android → **Віджети → Svitlo**.
Доступні **«Світло · графік»** (4×2, зі шкалою доби) і **«Світло · компактний»** (2×2).
Під час додавання виберіть точну адресу й підчергу. Кожен віджет має незалежні налаштування;
можна додати кілька віджетів для різних адрес. Для зміни вибору відкрийте налаштування віджета через меню лаунчера.

Натискання відкриває відповідну адресу в Svitlo. Кнопка ↻ ставить ручне оновлення в чергу Android
і працює також із вимкненим автоматичним оновленням. Без мережі завдання очікує з’єднання.
Віджети читають спільний кеш і перемальовуються після ручних та фонових перевірок, видалення адреси й зміни часу.
Дані старші за 15 хвилин, помилки мережі та відсутній сьогоднішній графік не показуються як підтверджений поточний стан.

Час стану й перевірки завжди вказаний; відлік та маркер відповідають часу останнього перемальовування.
Локальна перевірка стану запланована на чверть години та момент застарівання кешу без пробудження телефона.
Без дозволу точних сигналів Android може затримувати її. Періодичне оновлення лаунчера лишається резервом.
Віджет не додає нових дозволів і не запускає постійний сервіс.

## Інтерфейс 0.4.0

На головному екрані — вибір адреси та графіки на сьогодні й завтра. Кнопка поруч з адресою оновлює графік.
Шестерінка відкриває керування адресами, сповіщення, фонове оновлення, інформацію про джерело й технічні дані.
Поточний час позначено лінією з крапкою та часовою міткою над шкалою; поточний інтервал виділено в таблиці.
Непідтверджений кеш не показує поточний стан чи маркер часу. Світла й темна теми відповідають системі.

## Що працює

- Пошук населеного пункту → вулиці → будинку.
- Кілька збережених адрес; визначення всіх підчерг будинку через офіційний сервіс.
- Окремий графік кожної підчерги на сьогодні й завтра: шкала та таблиця півгодинних інтервалів.
- Інтервали графіка, відлік до відключення та сповіщення — за Києвом незалежно від часового поясу пристрою.
- Позначка «Оновлення на сайті обленерго» відтворює час із сайту джерела без додаткового зсуву часового поясу.
- Збереження останнього отриманого графіка. При помилці зв’язку він явно позначений як непідтверджений.
- Android: місцеві сповіщення за 15/30/60/120 хвилин до початку відключення або можливого відключення.
- Android: фонове оновлення всіх збережених адрес приблизно раз на 15 хвилин, навіть коли екран додатка закрито.
- Повідомлення про зміну інтервалів, підчерг або публікацію графіка на завтра; службова зміна дати оновлення не створює зайвих повідомлень.
- Збережені адреси старого прототипу підхоплюються; підчерги визначаються повторно.

Графік не показує фактичний стан мережі. Аварійні й екстрені відключення можуть відбуватися поза ГПВ.
Відсутність графіка, підчерги чи окремого інтервалу **не означає наявність електроенергії**.

## Запуск на комп’ютері

Потрібен [Node.js](https://nodejs.org/) 22 або новіший.

1. Завантажте репозиторій і відкрийте термінал у його папці.
2. Один раз виконайте `npm ci`.
3. Виконайте `npm start`.
4. Відкрийте **http://127.0.0.1:3000** у браузері й натисніть «Додати адресу».

Поки користуєтесь вебверсією, термінал має залишатися відкритим. Зупинка — Ctrl+C.

`npm start` збирає вебсторінку та запускає сервер. Він пересилає тільки п’ять дозволених публічних GET-запитів
до API обленерго. Це потрібно, тому що API не дозволяє браузерні запити з довільного домену.
Android отримує графіки системними HTTP-запитами без цього проміжного сервера.
Сторінка, відкрита як окремий HTML-файл або на GitHub Pages, без сервера API працювати не буде.
Публічний хостинг потребує Node-сервера, HTTPS і встановлення `HOST=0.0.0.0` та `PORT` у середовищі хостингу.

## Android

GitHub → **Actions** → **Test and build APK** → успішний запуск → **Artifacts** → **svitlo-android-debug**.
Розпакуйте ZIP і встановіть `app-debug.apk` на Android. Це тестова збірка, не публікація в Google Play.
Для завантаження Artifacts потрібно ввійти в GitHub; файли зберігаються 14 днів.
Збірки з `main` також потрапляють у **Releases**.

Під час першого ввімкнення сповіщень дозвольте повідомлення та, за потреби, точні сигнали Android.
У розділі **«Фонове оновлення»** є перемикачі перевірки графіків та повідомлень про зміни.
Фонове оновлення виконує Android WorkManager без WebView, орієнтовно раз на 15 хвилин за наявності інтернету.
Після зміни графіка додаток зберігає його, переплановує попередження й надсилає повідомлення.
Перша перевірка створює базовий графік без повідомлення про зміну. Публікація графіка на завтра вважається зміною.
Після повернення до додатка відображаються дані, завантажені фоновою перевіркою.

Кнопка **«Тест фонової перевірки»** запускає окрему перевірку орієнтовно через 30 секунд.
Згорніть додаток: повідомлення «Фонова перевірка працює» підтвердить виконання без відкритого екрана.
Якщо мережа або частина запитів недоступні, тест повідомить про помилку.

15 хвилин — мінімальний період WorkManager, а не гарантія точного часу. Android може відкладати перевірки
у режимі Doze, економії батареї або без мережі. Після **примусової зупинки** потрібно відкрити додаток знову.
На деяких телефонах у системних налаштуваннях потрібно дозволити автозапуск і роботу у фоні;
кнопка **«Налаштування роботи у фоні»** відкриває налаштування Svitlo.
Після перезавантаження телефона завдання й попередження відновлюються.

Попередження використовують останній успішно завантажений графік. Помилка зв’язку не видаляє його
та вже заплановані попередження, але в інтерфейсі дані позначаються як непідтверджені.
Видалення адреси скасовує її майбутні попередження; зміна графіка скасовує застарілі інтервали.

Для локальної збірки також потрібні Java 21 та Android SDK:

```sh
npm ci
npm run android:prepare
```

Потім у папці `android` виконайте `./gradlew assembleDebug` (Windows: `gradlew.bat assembleDebug`).
Файл: `android/app/build/outputs/apk/debug/app-debug.apk`.
Тестові APK з різних збірок можуть мати різні debug-підписи. Якщо Android не дозволяє оновлення,
потрібно видалити попередню тестову версію; це видалить збережені в ній адреси.
Для постійних оновлень потрібен окремо налаштований стабільний ключ підпису.
Приватні ключі не можна додавати в репозиторій чи публічні артефакти CI.

## Перевірка та структура

```sh
npm test
npm run build
```

Перевірка інтерфейсу (пошук адреси, збереження, мобільна ширина, кеш при помилці та перемикання адрес):

```sh
npx playwright install chromium
npm run test:ui
```

У CI вона використовує фіксовані відповіді API, щоб збій сайту обленерго не зривав збірку.
Для додаткової перевірки з реальним API встановіть змінну середовища `SVITLO_LIVE_TEST=1`.

- `src/core.js` — запити графіка, точне зіставлення підчерг, час, інтервали та сповіщення.
- `src/app.js` — інтерфейс, пошук, збереження адрес, системні API Android.
- `native/android/` — фоновий Worker, спільний з екраном кеш, системні попередження, відновлення після перезапуску й тести Android.
- `svitlo-ternopil.html`, `src/style.css` — шаблон і стилі.
- `server.mjs` — сервер вебверсії; не надає довільного проксі та не пересилає cookies користувача.
- `test/` — автоматичні перевірки формату, кількох підчерг, відсутніх даних, переходу через північ,
  київського часу, сповіщень і меж доступу вебсервера.

Залежності фіксуються в `package-lock.json`. `www/`, `android/` і `node_modules/` генеруються та не зберігаються в Git.
Вихідні файли з `native/android/` копіюються під час `npm run android:prepare`.
Android-перевірка: у папці `android` виконайте `./gradlew testDebugUnitTest assembleDebug`.
API не є документованим публічним контрактом: при зміні сайту обленерго інтеграція може потребувати оновлення.

Адреси й останні графіки зберігаються локально в додатку або браузері. Під час запиту ідентифікатори
населеного пункту, вулиці та номер будинку надсилаються обленерго; у вебверсії — через сервер Svitlo.
Технічний журнал додатка не містить параметрів адрес і повних відповідей API.
